## Optional specialist team profile (producer contract, 2026-10-05)

The customer assistant owns one problem through resolution or human handoff. The optional profile specializes the existing swarm_agent, swarm_team and swarm_supervisor FlowSpecs; it is not a new scheduler or a prerequisite to their use. Its target is ten Machines, each one team lead plus nine specialist subflow conversations: 100 fleet conversations, with root supervision separately counted. The topology is a target, not qualified capacity. Seagulled's existing smaller worker and provider-call limits remain unchanged.

The installable profile has `{id, logicalAgentTarget, topologyTarget:{workers,specialistSubflowsPerWorker}, binding:{model:'installed',requiredAgentServers,optionalAgentServers}, roles:[{id,mission,instructions,evidence}]}`. All roles share the installed model and connected tools. Role instructions narrow assignments, not permissions. Unsupported per-role model/tool bindings are rejected rather than multiplying concurrency gates. Required tools must exist. One existing subflow node bounds all children; the selected profile caps it at nine while the ordinary template retains ten. Independent verification and adversarial review are required role briefs.

Assignment prompts carry CASE_ID, AGENT_ID, ROLE_ID, ANGLE, TASK and DONE_WHEN; these are prompt obligations, not a new durable assignment table. Existing worker/run/conversation IDs and board receipts remain authoritative. Unknown execution and cleanup holds prevent replay. The customer-facing owner retains ticket creation and customer notifications; specialist agents prepare evidence only. Conversation-ID instrumentation and a live ten-by-ten run remain qualification work.

Selected-provider fleet route (October 5): ProviderManager.fleetRoute(providerId) is a backend-only credential lease, unavailable unless explicitly permitted by API Connect fleetAllowed:true. OpenAI uses openai-responses, Anthropic uses anthropic; Modal and native subscription remote routes remain unqualified. Provider publicState exposes only fleetEligible/fleetDetail, never model keys. Swarm passes the exact selected-provider route into the owned fleet path; legacy profiles supply tooling only, with no alternate model/provider fallback for product goals. API Connect must disclose credential use by isolated workers and local encrypted storage before enabling that permission. Eligibility is distinct from verified inference or qualified cloud execution. Budget unknown holds and original account/source/cleanup holds remain authoritative. Parent monetary receipt handling requires an actual finite nonnegative number; null/string/invalid reported or estimated receipts remain unknown, preserve pending allowance, and never become measured $0.

Provider fleet API implementation: `connect({id,method:'key',key?,model?,fleetAllowed?:boolean})` defaults `fleetAllowed` to false. `fleetSupported` is true only for OpenAI and Anthropic, regardless of connection state; `fleetEligible` is true only while connected, unblocked, and explicitly allowed. `fleetDetail` is a safe public explanation. A still-connected API key can be granted worker permission by calling Connect again with `{id,method:'key',fleetAllowed:true}` after disclosure; the manager reuses its current in-memory key and model. A restored encrypted-store or environment connection must first appear as connected through discovery. A blocked connection requires a newly supplied key; a disconnected connection cannot grant worker permission by keyless Connect. `fleetRoute(id)` returns `{available:false,detail}` or a backend-only `{available:true,providerId,model:{name,baseUrl,apiKey,provider,adapter},verification:'unverified',costPolicy:'pending'}`. Modal remains local-only and rejects `fleetAllowed:true`; its public `fleetSupported` and `fleetEligible` are false. The key appears only in the backend route, never in `publicState` or saved connection metadata.
